# ADR 0001: V2 硬删除与双水位线

- 状态：已采纳
- 日期：2026-09-06

## 背景

V1 同时用软删除字段、Dashboard 防复活墓碑和账单导出收据表达不同问题。订阅费用又从实时配置推导，导致已经删除的 Key 仍可能被错误计算、导出和重新复活。单一删除状态无法同时表示暂停、计划结束、历史事实和导出进度。

## 决策

Token-Board V2 与 Dashboard V2 采用物理删除的实时配置模型：

1. 实时行存在即表示配置存在；`enabled` 只表示暂停。
2. 经过确认的未来合同结束使用 `ends_at`，到期由统一生命周期模块硬删除。
3. 请求日志、稳定身份、冻结费用、分摊和导出事件是不可变历史事实，不承担实时生命周期。
4. Dashboard 删除物理删除账户、用量和周期费用；删除防复活墓碑、收据表和全量账户镜像。
5. 请求事实与账单事实分别使用独立水位线。导出只消费两个水位线之后、当前捕获上限以内的事实。
6. 费用按 Plan credential、Agent subscription instance 计费，常规运行只物化当前周期；未绑定软件的 Agent 费用没有 allocation，因此不进入实际消费。

## 后果

### 正面

- 删除不再通过隐式墓碑影响路由、订阅计费或历史账务。
- 计费、导出和报表可以分别依据稳定的自然键和不可变事实运行。
- 同一账单重复导入不会累计两次；不同机器的新请求仍可按增量合并。
- 没有新事实时，删除的 Dashboard 账户不会复活。

### 接受的权衡

另一台机器如果尚未导出删除前已经产生的事实，之后把这些事实作为新的增量导出时，Dashboard 允许重新建立账户。这是双水位线和无墓碑设计下的明确语义：系统只把事实是否已经被本机水位线确认作为边界，不猜测其他机器的导出进度。

升级需要 V1 pending 导出先按 V1 协议恢复；无法连接远端时拒绝升级而不是丢弃或猜测 pending 状态。V2 使用 shadow copy 和自动备份，升级失败保留原库并回滚。

## 不采用的方案

- 不保留 Dashboard 防复活墓碑或替代收据。
- 不用“删除状态”过滤实时配置查询。
- 不在常规 worker 中扫描所有历史冻结费用补建导出事件。
- 不提供 V1/V2 双写或字段兼容层。
